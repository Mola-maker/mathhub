# PGF/TikZ 3.1.11a capability matrix

## Pin and provenance

This catalog is pinned to the official PGF/TikZ release tag:

- Version: `3.1.11a`
- Tag/commit: [`839974a3f895bfb86f5a8bc155f0886c918f1bff`](https://github.com/pgf-tikz/pgf/tree/839974a3f895bfb86f5a8bc155f0886c918f1bff)
- Official manual: [PGF/TikZ manual (1323-page PDF)](https://pgf-tikz.github.io/pgf/pgfmanual.pdf)
- Release page: [3.1.11a release](https://github.com/pgf-tikz/pgf/releases/tag/3.1.11a)
- Repository: [pgf-tikz/pgf](https://github.com/pgf-tikz/pgf)

Every catalog `officialRef.source` points to a source file at the pinned
commit; `officialRefUrl` is a URL-only alias for the shared official manual.
The PDF link is intentionally shared by entries because the manual's
internal anchors are not a stable API; the `section` field names the chapter
or library section to search in that PDF.

The implementation is in [`lib/tikz/syntax`](../../../lib/tikz/syntax):

- `types.ts` contains the version, layer, recognition, capability, risk, and
  exhaustive library-name types.
- `catalog.ts` contains the major chapter entries and one entry for each of
  the 74 generic `tikzlibrary*.code.tex` files in this release.
- `query.ts` provides ranked search, summary aggregation, and the AI compact
  schema.

The pinned catalog currently contains 140 entries: 66 major chapter/layer
records plus the 74-library table.

## What the flags mean

Each entry has the same five booleans. They are separate lanes, not a single
support score:

| Flag | Meaning in Math GeoHub |
| --- | --- |
| `preserve` | Source transactions retain untouched bytes, comments, formatting, and unknown TikZ blocks. |
| `syntax` | The token/command/library surface is discoverable by the catalog and parser boundary. It does not promise TeX expansion. |
| `semantic` | A stable semantic projection exists for the supported subset (coordinates, dependencies, constraints, and so on). |
| `interactive` | A Canvas operation can safely produce a minimal upstream source patch for this construct. |
| `exact` | The isolated TeX compilation lane can render the construct. Engine/driver/Lua prerequisites are recorded in `notes` and `securityRisk`. |

The current matrix intentionally gives the official surface `preserve: true`,
`syntax: true`, and `exact: true` while narrowing `semantic` and
`interactive` to known adapters. **Full exact/preserve coverage is not Canvas
editability.** For example, a graph-drawing layout, a `pgffor` loop, a driver
primitive, and a pattern are preserved and can be sent to TeX, but the Canvas
must not pretend that an arbitrary TeX expansion is a draggable object.

## Layer-level matrix

The catalog covers the requested manual boundaries. The table describes the
default profile; individual entries may be stricter.

| Layer | Recognition | Preserve | Syntax | Semantic | Interactive | Exact | Main risk boundary |
| --- | --- | :---: | :---: | :---: | :---: | :---: | --- |
| Core TikZ | static, TeX expansion, driver | ✓ | ✓ | subset | subset | ✓ | macro expansion and backend output |
| Graph Drawing | TeX expansion / driver | ✓ | ✓ | layout projection | — | conditional | sandboxed LuaTeX and optional OGDF/native bindings |
| Libraries | static, TeX expansion, driver | ✓ | ✓ | adapter subset | adapter subset | ✓ | library-specific expansion, files, or driver output |
| Data Visualization | TeX expansion | ✓ | ✓ | data/axis subset | — | ✓ | data expansion and resource limits |
| Utilities | TeX expansion / driver | ✓ | ✓ | key/math subset | — | ✓ | loops, keys, page/shipout effects |
| Math engines | TeX expansion | ✓ | ✓ | expression subset | — | ✓ | expansion depth, precision, resource exhaustion |
| Object engines | TeX expansion | ✓ | ✓ | — | — | ✓ | arbitrary object/class macros |
| Basic layer | static, TeX expansion, driver | ✓ | ✓ | path subset | path subset | ✓ | backend resources and external assets |
| System layer | driver | ✓ | ✓ | — | — | conditional | output-driver contracts |

The summary function reports exact counts and the IDs where
`preserve && exact && !interactive` is true. This keeps the distinction
visible to UI and AI callers instead of burying it in prose.

The count is 74. `pgfplots` is not included: it is a separate package, not an
official PGF/TikZ 3.1.11a built-in library. The externalization implementation
(`tex/latex/pgf/frontendlayer/libraries/tikzlibraryexternal.code.tex`) and the
Graph Drawing modules (`tex/generic/pgf/graphdrawing/tex/...`) are tracked as
their own driver/Graph Drawing entries rather than being misrepresented as
members of the 74 generic front-end library tuple.

## Recognition and security profile

- `static` means a source parser can classify the construct without executing
  TeX. Core paths, coordinates, and many shape options use this profile.
- `tex-expansion` means keys, macros, arithmetic, graph/data expansion, or
  object methods affect the meaning. Parsing and semantic projection must stay
  separate from execution.
- `driver` means the final behavior is selected by a TeX output backend (PDF,
  SVG, dvisvgm, and so on). Browser SVG rendering is not claimed to be byte or
  pixel identical to every driver.

`securityRisk` is per entry and always includes a summary plus mitigations.
High-risk entries include Graph Drawing/Lua, native OGDF bindings, RDF/network
references, and external assets. The catalog does not grant shell escape,
filesystem, network, or native-process privileges. Untrusted TeX remains an
isolated compiler concern, never a Next.js-process operation.

## Query and AI usage

```ts
import {
  TIKZ_LIBRARY_NAMES,
  queryTikzSyntaxCapabilities,
  summarizeTikzSyntaxCapabilities,
  createTikzAiCompactSchema,
} from '@/lib/tikz/syntax';

const positioning = queryTikzSyntaxCapabilities({ library: 'positioning' });
const interactive = queryTikzSyntaxCapabilities({ capabilities: { interactive: true } });
const summary = summarizeTikzSyntaxCapabilities();
const aiPayload = createTikzAiCompactSchema();
```

The compact schema keeps the ordered capability bit string `p s m i e` (for
example `ps-ie` means preserve, syntax, interactive, and exact), the risk level,
search tokens, and the pinned source metadata. It is deliberately a retrieval
schema, not permission to execute the corresponding TeX.
